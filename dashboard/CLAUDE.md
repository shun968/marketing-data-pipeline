# CLAUDE.md — dashboard

開発ルール・ADR・レポート・ガードレールメトリクスのモニタリング画面（Python 3.11+ / uv）。

リポジトリ全体の規約（Pythonの書き方を含む）はルートの `CLAUDE.md` にある。ここには**この領域に固有の規約だけ**を置く。

## 開発コマンド

```sh
uv sync                     # 依存インストール
uv run pytest               # テスト
uv run ruff check .         # lint
uv run ruff format .        # フォーマット
uv run dashboard            # 起動（http://127.0.0.1:8787）
uv run dashboard --reload   # 開発用。ソース変更で自動再起動
```

## 外部に開かない

**bind先を 127.0.0.1 から動かさない。CLIにホスト引数を足さない。**

この画面は収集データをそのまま表示する。レポート本文には投稿の引用が入り、収集ログにはキーワードと件数が、キーワード実績には検索語の全量が出る。`0.0.0.0` で待ち受けると同一ネットワークの他端末から全部読める。

外部から見る必要が出た場合は既定を変えず、SSHのポートフォワードを使う。

この制約は `tests/test_app.py::test_bind先が127001に固定されている` が固定している。**ホスト引数を足すとテストが落ちる。** 落ちたときに「テストを直す」のではなく、なぜ落ちたかを読むこと。

## URLから来た文字列でファイルを開かない

レポート本文のパスだけがURLから来る。必ず `paths.resolve_within()` を通し、解決後の実パスが許可ルート配下にあることを検証する。

- **文字列で `..` を弾く方式にしない。** シンボリックリンクが外を指す場合を捕まえられない
- 新しく「パスを受け取るエンドポイント」を足すときは、`tests/test_app.py` のトラバーサル系ケースを同じ数だけ足す

読み取りを許可するディレクトリは `paths.Roots` に列挙してある。ここに無い場所は読まない。

## 表示は検査ではない

**壊れた入力で画面を落とさない。** 書式違反のADR、解釈できないログ行、破損したJSONL行は、落とさず「不明」として出すか、その行だけ飛ばす。

書式は `scripts/check-adr-format.sh` が、記録の形式は `scripts/record-check.sh` が別途強制している。閲覧側が二重に検査すると、**壊れた状態を確認するために画面が使えない**という逆転が起きる。

## 集計の範囲と表示の範囲を分ける

ログは追記され続けるため表示は直近に絞る。**同じ定数で集計まで絞らない。**

「累計」と称した値が実測の半分（bluesky 11,658件 → 5,742件）になった実績がある。しかも画面上は変化として見えず、キーワード改訂の判断材料がそのまま狂う。

切り詰めるなら、切り詰めたことを**数値を出している場所に**表示する。表の上のヒントでは読み手に届かない。

## 途中で終わった処理を見分けられる形にする

収集ログは `start:` と `done:` の対で1実行になる。**`done:` の無い実行を正常な最終実行として出さない。**

`sns-collector/CLAUDE.md` が記録しているとおり、このリポジトリの主要な失敗モードは途中終了（HTTPエラーでの打ち切り）である。完走したかどうかが分からない実行結果の画面は用をなさない。

解釈できないログ行も捨てない。保存先・保存件数・エラーはそこにしか出ない。

## 列挙したものが参照時に在るとは限らない

`rglob` / `glob` で並べたパスは、`stat()` や `read_text()` の時点で消えていることがある。切れたシンボリックリンク、列挙中の削除、権限のないファイルのいずれでも例外になる。

**1件の異常で画面全体を落とさない。** 読めないものは一覧から外す。`/` は複数のソースを束ねるため、1つのディレクトリの異常がトップページごと500にする。

`resolve_within()` はルート外を弾くだけで、**ルート内を指す壊れたリンクは通す**。パスの検証と読めるかどうかは別の話として扱う。

## メトリクスの入力

`.metrics/guardrail-events.jsonl` を読む。書き手は `scripts/record-check.sh` で、スキーマとルールIDの決め方はそちらの先頭コメントにある。ここには書き写さない。

集計の用途はガードレールの見直しであり、**候補を挙げるところまでに留める**。「このルールは不要」と断定しない。一度も発火していない検査が抑止力として効いている場合があり、剥がすかどうかは人が決める。

## テンプレート

- **外部CDN・外部フォントを参照しない。** ローカルに閉じた画面である前提が崩れる
- Markdownは `markup.render()` を通す（生HTMLはエスケープされる設定にしてある）

## テスト

- 実リポジトリを読まない。`repo` フィクスチャが `DASHBOARD_REPO_ROOT` を差し替える
- データが1件も無い状態（初回起動）で全画面が開くことを常に担保する
- **壊れた入力を1件混ぜて画面が200を返すことをテストする。** タイムゾーンなしのタイムスタンプが1行混ざるだけで、`sorted()` の比較が `TypeError` になり3画面が500になった実績がある。パース関数のtry内だけを見ても捕まらない
