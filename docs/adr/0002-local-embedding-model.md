# ADR-0002: 埋め込み生成はローカルモデルで行う

- ステータス: 採用
- 日付: 2026-07-28
- 関連: [requirements.md](../requirements.md) N-02 / [design.md](../design.md) §4.4

## コンテキスト

意味検索（F-10）とクラスタリング（F-11）にはベクトル埋め込みが必要である。クラウドの埋め込みAPI（OpenAI、Vertex AI、Cohere等）は品質と手軽さで優れるが、投稿テキストを外部へ送信することになる。

一方、構造化抽出（ADR-0003）ではClaude Code経由で投稿本文をAnthropicへ送信する方針を採っている。「抽出では送るのに埋め込みでは送らない」のは一見不整合に見えるため、判断の根拠を明記する必要がある。

### 検討した選択肢

| 案 | 却下理由 |
|---|---|
| クラウド埋め込みAPI | 検索のたびに外部送信・従量課金。モデル変更時の全件再生成コストが大きい |
| 埋め込みを使わず全文検索のみ | 表記揺れ（「面倒」「めんどい」「だるい」）を吸収できず、F-10を満たせない |
| Claude Code経由で埋め込み生成 | 埋め込みは数値ベクトルの生成であり、対話セッション経由での取得は非現実的 |

## 決定

**埋め込み生成はローカルモデルで行い、外部APIを使用しない。**

判断の根拠:

1. **抽出と埋め込みは頻度が2桁違う。** 抽出は1投稿につき1回だけ（結果を凍結するため）。埋め込みは検索クエリのたびに発生し、モデル変更時には全件再生成が必要になる。外部APIに依存すると、検索という日常操作のたびに外部送信と従量課金が発生する。
2. **追加課金を発生させない（N-04）。** ローカルモデルなら再生成コストがゼロで、モデルの入れ替え・比較を気軽に試せる。
3. **オフラインで完結し、cronで無人実行できる。** APIキー管理・レート制限・障害対応が不要になる。
4. **埋め込み対象は要約文であり短い。** 抽出済み `summary`（1文）を埋め込むため、長文をローカルで処理する必要がない。ローカルモデルでも十分な速度が出る。
5. **埋め込み品質の要求水準が抽出ほど高くない。** 検索は「候補を絞る」ためのものであり、最終判断は人間が投稿本文を読んで行う。多少の精度差は運用で吸収できる。

## 結果

- 検索・クラスタリングが外部送信を伴わない。モデルの入れ替えと全件再生成を課金なしで試せる
- 埋め込み品質はクラウドAPIに劣る可能性がある。検索を「候補の絞り込み」に留め、最終判断を人間が行う運用でこれを吸収する
- 推論速度が実行環境のCPU/GPUに依存する。長文ではなく要約文（1文）を対象とすることで負荷を抑える
- **具体的なモデルは未選定（未確定事項 O-02）。** Phase 3 で実データを用いて選定し、結果を本ADRへ追記する。選定基準は次の4点。
  - 日本語の意味的類似性の精度
  - 実行環境のCPU/GPUで許容できる推論速度
  - ベクトル次元（ストレージと検索速度に影響）
  - ライセンス
